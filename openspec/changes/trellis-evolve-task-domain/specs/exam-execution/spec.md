# Spec Delta

## Purpose

考题验证的执行契约:沙盒化重跑、副作用 mock、完整轨迹保留、预算与模型可配置——让候选配置的验证安全(永不伤真实环境)、可审计(过程可回放)、成本可控。

## ADDED Requirements

### Requirement: 验证永不重放原任务
验证 SHALL 只执行蒸馏考题;用户的原始任务 SHALL NOT 被系统执行——真实任务的副作用("发邮件"会真发出去)永不进入执行面。考题执行时,副作用类工具 SHALL 按考题的副作用声明被拦截(见「沙盒执行与副作用 mock」),从执行结构上保证不可能产生真实外部效果。

#### Scenario: 原任务从不被执行
- **WHEN** 系统对某真实任务的蒸馏考题执行验证轮
- **THEN** 只有考题在沙盒内被执行,原任务的任何动作(发送/部署/删除)未发生

### Requirement: 沙盒执行与副作用 mock
考题执行 SHALL 在隔离沙盒内进行:临时 workspace、重定向的配置 HOME(candidate 配置经渲染装入)、源材料只读。副作用工具(发邮件/部署/删除/外呼 API 等)SHALL 按副作用声明拦截为 mock——执行结果为沙盒内记录(如 mock outbox),交付物是文本/产物而非真实动作;安全工具(沙盒内文件读写、计算)SHALL 正常执行。出网 SHALL 默认封锁(仅允许模型 API 端点)。

#### Scenario: mock outbox 记录而非发送
- **WHEN** 考题声明"发邮件"为副作用动作,执行中 agent 调用发送工具
- **THEN** 邮件被写入沙盒 mock outbox,没有任何邮件真实发出

#### Scenario: 出网默认封锁
- **WHEN** 执行中的 agent 尝试访问非模型 API 的外部地址
- **THEN** 访问被拒绝,尝试记入轨迹

#### Scenario: 源材料只读
- **WHEN** 执行中的 agent 尝试修改源材料文件
- **THEN** 修改被拒绝,源材料保持逐字节不变

### Requirement: 完整轨迹保留
每次 rollout 的执行过程 SHALL 以完整轨迹保留(共享语法 `[ACTION]/[OBSERVATION]/[ERROR]`,不为提示词预算截断),随运行目录存档;轨迹中的错误段 SHALL 保留原样。被采纳的配置改动 SHALL 可指认到具体轨迹时刻作为证据。

#### Scenario: 轨迹完整入档
- **WHEN** 一次 rollout 执行完毕(含报错步骤)
- **THEN** 运行目录含完整轨迹文件,错误段在轨迹中可见,未经截断

### Requirement: 执行预算与模型可配置
单轮验证的沙盒会话上限、USD 上限,以及提案/执行/判分三角色的模型 SHALL 可配置(缺省保守:单轮 ≤8 次沙盒会话);执行账本 SHALL 保持预算恒等式(实际执行次数与预算推算不符即终止本轮)。**手动触发铁律**:付费执行与付费提案调用 SHALL 只由手动触发或人批准的时机执行;事件触发路径 SHALL 零花费(只做观察与蒸馏线索采集)。

#### Scenario: 超预算即停
- **WHEN** 本轮执行次数达到配置上限
- **THEN** 本轮终止,已执行部分入账,不再发起新执行

#### Scenario: 模型可配置
- **WHEN** 用户在配置中指定判分模型
- **THEN** 该模型用于判分,未指定时用缺省;配置变更不要求改代码

#### Scenario: 事件触发零花费
- **WHEN** 事件触发路径运行
- **THEN** 无任何付费模型调用或沙盒执行发生,只记录观察与蒸馏线索

### Requirement: 执行沙盒失败收口
执行/判分失败 SHALL 收口而非中断整轮:一次 rollout 失败记为该臂未交付(进入选择侧的不采纳语义);判分失败记 None(永不记 0,不进分母);沙盒残留 SHALL 被回收(临时目录清理,崩溃残留有回收机制)。

#### Scenario: rollout 失败不影响整轮
- **WHEN** 候选臂的一次执行因超时被终止
- **THEN** 该臂记为未交付,选择侧按"任一臂未交付不采纳"收口,其余臂与档案不受影响
