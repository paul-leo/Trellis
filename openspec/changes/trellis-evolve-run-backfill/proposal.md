# Proposal

## Why

进化循环今天只有事件驱动一个入口:作业在会话边界被触发器拉起,阈值/冷却/预算任一不满足即跳过。两个真实需求因此落空:用户想**手动触发一次进化**(立刻跑,不等会话边界与冷却);用户想用**历史会话数据**做观察与进化(老数据是宝贵财富,但观察面从扩展装载那刻才开始记,开启之前的会话永久不可见)。同时要补上防重复缺口:作业运行期间到达的触发(含将来的手动触发)今天被**静默丢弃**,既不排队也不补跑;历史数据若可导入,必须有导入幂等,否则重复导入 = 重复信号 = 重复提案。

## What Changes

- **手动触发** `trellis evolve run`:显式用户触发一次一次性作业,与事件触发跑同一作业体。绕过信号阈值与冷却(用户明确意图),仍守单飞作业锁与日提案上限/editor 预算(护栏不放)。提供 `--dry-run` 预览将做什么而不拉起作业。级别闸不变:`observe` 及以下零副作用早退并在输出中说明。
- **历史数据导入** `trellis evolve import <path>...`:用户显式选定的 session 数据(首个适配器:Claude Code 会话 JSONL)→ 按观察信号同一字段白名单抽取元数据信号(**不入库任何入参/结果载体**),写前一律 secrets 擦除。导入台账幂等:源文件身份(内容摘要)+ 已导条目记账,重复导入为空操作;信号 stableId 确定性(`import:<源摘要>:<序号>`),配合既有 rule-`<findingId>` 提案同源去重,重复数据不会变成重复提案。
- **防重复(单槽补跑,非常驻队列)**:运行期间到达的触发请求(手动或事件)SHALL 合并为至多一个"待补跑"标记(多次请求塌缩为一次);当前作业收尾时消费标记并链起至多一次补跑;标记亦可由下次事件触发/手动 run 消费。不引入常驻进程与 FIFO 队列——系统保持 daemon-less。
- **运行档案可观测**:job-run 记录触发来源(`event` / `manual` / `chain`),触发判定档案记补跑标记的置位/消费;`report`/GUI 时间线沿用现有聚合透传,无新消费面。

## Capabilities

### New Capabilities

(无)

### Modified Capabilities

- `self-evolution`:
  - 修改「触发是事件驱动的一次性作业」:增加手动触发入口与"运行中请求合并为单槽补跑"语义(取代该情形下"静默丢弃");事件路径的阈值/冷却/预算跳过语义不变。
  - 修改「管理面命令不触发进化循环」:查看类命令仍不触发;`run` 为唯一显式触发入口(与事件触发同作业体、同护栏)。
  - 新增「历史数据导入与幂等回填」需求:显式选定源、元数据白名单、擦除、导入台账幂等、确定性 stableId。

## Impact

- 代码:`src/commands/evolve.ts`(run/import 子命令)、`src/evolve/trigger.ts`(补跑标记与消费)、`src/evolve/jobMain.ts`(收尾链起 + 触发来源入档)、新增 `src/evolve/importHistory.ts`(适配器契约 + Claude Code JSONL 首个适配器 + 导入台账)、`src/evolve/recorder.ts`(信号 source 增 `history-import`)、`src/evolve/types.ts`;报告/CLI 渲染透传新字段。
- 测试:trigger 补跑塌缩、jobMain 链起上界、import 幂等/擦除/白名单、run 的级别闸与护栏、管理面不变性回归。
- 不动:引擎包、L1/风险/采纳门语义、备份回滚、GUI 结构(仅透传字段)、agent-bridge 探测;不经 MCP 协议(导入与手动 run 均为本机文件/进程操作)。
