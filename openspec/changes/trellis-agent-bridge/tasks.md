## 3. Delegation depth guard

- [x] 3.1 Read the current delegation depth from `TRELLIS_DELEGATION_DEPTH` (`readDelegationDepth` in `src/lib/agentBridge.ts`, default 0 when absent) and compare it against `maxDepth` from `agent-bridge.yaml` (default `DEFAULT_MAX_DELEGATION_DEPTH = 2`) in `AgentBridgeProvider.callTool` before calling `runDelegatedCall` at all; verified a call at `depth == maxDepth` is refused with a depth-limit error and never reaches `runDelegatedCall` (`AgentBridgeProvider: refuses a call at the delegation depth limit, spawning nothing`).
- [x] 3.2 `runDelegatedCall` sets `TRELLIS_DELEGATION_DEPTH=<depth + 1>` on every spawned child's environment (merged with the inherited `process.env`, so real credentials still flow through); verified the child observes the incremented value via a stub CLI `env` mode (`runDelegatedCall: propagates depth + 1 to the child's environment`, `AgentBridgeProvider: a call below the depth limit proceeds and increments depth for the child`). A live 3-hop real-process chain was not separately constructed — the env-propagation mechanism plus the provider-level ceiling check together are what a longer chain would rely on, and both are independently verified.
