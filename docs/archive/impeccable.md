## Design Context

### Users

Trellis is for developers who work with more than one Code Agent and need one
reliable place to manage Skills, MCP, Memory, shared instructions, migration,
and runtime delivery. They encounter the product in a terminal, a repository,
or a technical social post; the visual system should communicate control and
clarity quickly without requiring a product demo.

### Brand Personality

Precise, calm, infrastructural. The brand should feel trustworthy and
technical without looking dark, aggressive, or like a generic AI product. The
emotional goal is confidence: many agents can move through one coherent
runtime while context stays intact.

### Aesthetic Direction

Refined minimalism with a single-color line symbol and an editorial,
print-friendly light canvas. The core metaphor is a trellis: independent
agent paths are guided into one shared structure and can branch out again.
Use restrained near-black ink, warm paper-white, and at most one quiet accent
when a poster needs emphasis. Avoid multi-color marks, dark badge logos,
neon gradients, glossy sci-fi effects, and generic circuit-board decoration.
Social posters should be 3:4 portrait assets (1080 x 1440) with a subtle
technical grid or alignment detail, generous space, and a clear reading path.

### Design Principles

1. Express the product promise visually: many agent paths, one shared runtime.
2. Use one memorable geometric gesture instead of a collection of decorative
   parts.
3. Let typography and spacing carry hierarchy; color is a controlled signal,
   not the identity.
4. Make technical detail quiet and structural: guides, nodes, and coordinates
   should explain the system rather than decorate it.
5. Every asset must remain legible and recognizable when reduced to a small
   logo or viewed quickly in a social feed.
