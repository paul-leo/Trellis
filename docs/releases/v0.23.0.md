# Trellis v0.23.0

Shared memory now ships with an Agent-facing guide and a single primary
query path. Enabling the local graph backend also delivers `trellis-memory`
to the Agents whose scope and routes allow it. Markdown becomes review and
archive material while that backend is enabled. Pi native MCP delivery no
longer regresses to a duplicate bridge when version probing fails.

## Changes

- **Memory tools and guidance travel together.** Native Skill projection and
  Runtime Skill discovery use the memory backend's managed-agent, scope and
  route boundaries. MCP sync installs a missing guide and its resources for
  existing installations, reconciles its owned links when memory is disabled
  or scoped away, and leaves unrelated Skills to ordinary Skill sync.
- **One primary shared store.** With an enabled `memory` backend, the Runtime
  withdraws canonical Markdown memory tools/resources and rejects cached
  calls to them. The graph's MCP tools provide recall and mutation. Legacy
  canonical reads remain available without a shared backend; custom read-only
  MemoryProvider implementations remain supported.
- **Archives do not repopulate live memory.** `trellis memory export` creates
  private JSONL/Markdown snapshots under
  `~/.trellis/archive/memory/snapshots/`, preserving the graph. Filenames
  distinguish names that normalize to the same slug. The CLI's `memory extract`
  is now an alias for this archival export, rather than a graph-to-canonical
  import. The older extraction SDK helpers remain maintenance APIs.
- **Online writes stay with MCP.** Onboarding stages/reviews native Markdown
  and reports conflicts without applying a graph-file snapshot. Legacy
  `memory sync` requires explicit `--offline` for real writes; all graph writers
  must be stopped for that maintenance operation. `--dry-run` remains read-only.
- **Reproducible default backend.** New default definitions pin
  `@modelcontextprotocol/server-memory@2.1.0` and launch it with Node 24.22.2
  through npx. Trellis can keep its own supported Node runtime. The first
  backend launch needs registry access; existing custom definitions are kept.
- **Explicit legacy review.** The guide includes a bounded, read-only Claude
  history migration helper for the exact selected workspace. It reads indexed
  candidates and rejects private files, escapes and oversized files. Original
  native memories are preserved; automatic extraction/capture is not enabled.
- **Pi stays on native MCP.** Version probes use the PATH command first, then
  known user launcher paths only on ENOENT, covering Volta shim lookup from
  Node children. If probing is unavailable but the existing native config
  matches Trellis ownership, sync keeps native delivery and can retire an
  owned duplicate bridge. Legacy bridge compatibility remains in the package.

## Upgrade notes

```sh
volta install agent-trellis@0.23.0
trellis skill update-builtin
trellis sync skills --global-only
trellis mcp sync --global-only
trellis doctor
```

Use the package manager that owns your existing installation. Refresh the
Agent's MCP connection after upgrading; an already-running stdio Runtime
keeps its loaded code. Existing pi sessions may need `/reload` or a restart
to unload a retired bridge extension.

Review existing canonical/native memory before moving facts into the graph.
This release does not delete native directories, copy entire histories into
the graph, enforce graph-level project isolation, or install lifecycle hooks.
The `trellis-memory` Skill describes the explicit migration and save workflow.

The changed `memory extract` destination and the offline requirement for
legacy file sync are intentional behavior changes. Use `memory export` for
snapshots and Memory MCP tools for online updates.
