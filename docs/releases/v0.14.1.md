# Trellis v0.14.1

This patch release unblocks `pi mcp login` against providers that gate OAuth
dynamic client registration by client name — Figma being the known case
(its registration endpoint rejects pi's default `client_name` with a bare
403 while the MCP server is in beta).

## Changes

- Canonical `auth` object form gains an optional `client_name` — a public,
  self-asserted display name (not a credential; the secrets-policy scan stays
  scoped to `client_id`/`client_secret_env`):

  ```yaml
  figma:
    transport: http
    url: https://mcp.figma.com/mcp
    auth:
      kind: oauth
      client_name: Claude Code
  ```

- The pi renderer emits that as `oauth: { clientName }` in the mcp.json
  entry — byte-identical to what `pi mcp add --oauth-client-name` writes —
  so pi registers under the allowlisted name and subsequent
  `trellis mcp sync` runs converge instead of stripping the block.
- Servers without `client_name` are unchanged (bare `{url}`); other agents'
  renderers are untouched.

## Upgrading

CLI: `npm install -g agent-trellis@0.14.1`.

pi users hitting a 403 at `pi mcp login figma`: add `client_name` as above,
run `trellis mcp sync`, then `pi mcp login figma` again.
