# Trellis v0.13.0

This release makes OAuth credentials operable day-to-day: a renewal command,
a doctor health check, honest credential-health reporting in the Runtime
status tool, and a browser callback page that closes the authorization loop
cleanly.

## Changes

- `trellis mcp renew` silently refreshes every Trellis-owned stored OAuth
  token, suitable for scheduled runs (cron/launchd). Exit code is non-zero
  when any token needs attention, so schedulers can alert.
- `trellis doctor` gains an OAuth credential health check over the same
  shared classifier (`classifyStoredToken`), reporting `valid` /
  `no-token` / `expired-renewable` / `needs-auth` / `unreadable` with
  remediations.
- `trellis.mcp.status` gains an `oauth` section reporting credential
  health for OAuth-classified servers in scope, plus a structured
  `toolCount` on every upstream status. Agent-owned servers report
  `agent-managed` — Trellis never infers native authorization state from
  its own token store, per the v0.12 ownership semantics.
- Renewal, doctor and status reporting all scope to `owner: trellis`
  servers only; agent-owned servers are excluded from renewal and never
  reported as failures.
- The OAuth browser flow lands on a built-in callback page with clear
  success/failure feedback instead of a bare JSON response.

## Upgrading

CLI: `npm install -g agent-trellis@0.13.0`.

No configuration changes required. To keep Trellis-owned tokens fresh,
schedule `trellis mcp renew` (e.g. daily). Agent-owned OAuth servers keep
their existing native authorization flow.
