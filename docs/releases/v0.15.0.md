# Trellis v0.15.0

This minor release adds **workspace scope**: a second canonical layer that
lives in the project repo itself, so MCP servers, skills, and instructions
can be managed per-project and committed alongside the code.

## Changes

- **Project-layer canonical at `<repo>/.agents/`** — `config.json` (same
  snake_case `mcp.servers` schema and validator as `servers.yaml`),
  `AGENTS.md`, and `skills/`. Discovered by walking up from the cwd
  (`~/` itself never counts as a workspace root) and merged
  workspace-wins-by-ID, with `{ "enabled": false }` tombstones that
  suppress a global server for that project only.
- **Layer-preserving delivery** — global content renders only from the
  pre-merge global layer and never into project files; workspace entries
  go to every managed agent's native project path (Claude `.mcp.json` +
  copied `.claude/skills/`, Codex `.codex/config.toml`, Kiro
  `.kiro/settings/mcp.json` + steering, pi `.pi/mcp.json`, Kimi
  `.kimi-code/mcp.json`, zcode `zcode.json` with a reverse-precedence
  warning). Shadowed globals keep rendering globally with their global
  definition.
- **Committable by design** — `config.json` refuses credential-shaped
  literals at load (`${VAR}` references only), rendered artifacts never
  carry resolved secrets, and the committed ownership manifest lets a
  fresh `git clone` or `cp -R` copy re-attach cleanly instead of
  conflict-guarding its own artifacts.
- **CLI** — `trellis init --workspace`; `trellis sync` auto-includes the
  workspace layer (with `--check` as the CI freshness gate and
  `--global-only` as the escape hatch); `trellis mcp add --workspace` /
  `trellis skill add --workspace`; `trellis migrate --workspace` scans
  all six agents' project-level paths, classifies seven ways, extracts
  plaintext secrets into the global store (git-tracked literals get a
  rotation advisory), and runs inside one backup session so a single
  `trellis rollback` restores every original.
- **Doctor** reports per-entry layer attribution plus shadowed/tombstoned
  lists; `mcp sync`/`sync` conflict reports now print the remediation
  step instead of leaving the user at "left untouched".

## Upgrading

CLI: `npm install -g agent-trellis@0.15.0`.

Existing setups are untouched — outside a repo carrying `.agents/`,
behavior is byte-identical to v0.14.x. To adopt a project's existing
hand-written configs, run `trellis migrate --workspace --dry-run` at the
repo root first, then `trellis migrate --workspace`.
