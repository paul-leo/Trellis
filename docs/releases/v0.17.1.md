# Trellis v0.17.1

When an expired OAuth credential's refresh token was rejected with
`invalid_grant`, `trellis mcp auth <name>` exited with the provider's error
instead of starting another login. This patch lets the same command recover
the connection without requiring `--force`.

## Changes

- A rejected refresh grant starts a new browser authorization from the
  explicit `mcp auth` command. A successful silent refresh still needs no
  browser.
- Structured OAuth errors take precedence over HTTP status codes, so
  `invalid_request`, rate limits, and temporary provider failures do not
  trigger another login.
- The prior credential is replaced only after authorization succeeds;
  cancelling login preserves the existing file. JSON output remains valid
  and contains no token values.
- Background renewal and the gateway continue to report authentication
  failures without opening a browser.

## Upgrading

CLI: `npm install -g agent-trellis@0.17.1`.

If a refresh grant has expired or been revoked, run
`trellis mcp auth <name>` and complete the browser login.
