# Trellis v0.18.0

The gateway baked each OAuth upstream's `Authorization: Bearer` header once
at connect time and never looked at it again. A session that outlived the
access token (about an hour on morphix) 401'd on every tool call until the
agent restarted, and a re-authorization run with `trellis mcp auth` in
another terminal was invisible to the running gateway. Credentials are now
resolved per request, through the SDK's `AuthProvider` seam — no restart,
no new session.

## Changes

- **Per-request credential resolution.** For Trellis-owned OAuth http/sse
  upstreams, the gateway resolves the credential from the server's stored
  OAuth file as each outbound request's headers are assembled. A token
  written by any process — including `trellis mcp auth` in another
  terminal — is picked up by the very next request. There is no in-memory
  cache; the token file is the single source of truth.
- **Early refresh window widened to 5 minutes on the request path.** A
  tool call whose stored token is inside the window refreshes and persists
  it before the request goes out, so a request that passes the freshness
  check cannot carry a token that dies mid-flight. `trellis mcp auth` and
  background renewal keep their existing semantics (the 60s default skew
  in the store is untouched).
- **401 recovery without a restart.** When the provider rejects a token
  early (revoked before expiry), the gateway forces one refresh — under
  the same per-server lock and rotation semantics, bypassing the expiry
  check — and the transport retries the request once. The agent observes
  no error.
- **Dead grants isolate to one server.** If the forced refresh is rejected
  (`invalid_grant`), only that server's call fails, with an error carrying
  the `trellis mcp auth <name>` remediation. The server's gateway status
  reports auth-required with `requiresSessionRestart: false` — once the
  human re-authorizes, the running gateway recovers on its next request
  and the status self-heals to ready. Every other upstream keeps serving;
  no browser is ever opened by the gateway.
- **Pre-request refresh failures never abort the request.** If the
  credential check itself fails (network error, rejected grant), the
  request is sent with the previous credential and the 401 path decides
  the outcome.
- Explicit `Authorization` headers configured in canonical still take
  precedence; stdio upstreams, non-OAuth upstreams, and the connect-time
  resource-binding check are unchanged.

The SDK contract this relies on — `token()` called per request,
`onUnauthorized` awaited then one retry, a thrown `RefreshError`
propagating to that single call without poisoning the transport — is
pinned by tests against a real `StreamableHTTPClientTransport` and a real
local OAuth-protected MCP server, not mocks.

## Upgrading

CLI: `npm install -g agent-trellis@0.18.0`.

No configuration or stored-credential migration. Running gateways pick the
new behavior up when their agent session starts a new gateway; already
running sessions keep the old behavior until they restart — which is the
problem this version removes going forward.
