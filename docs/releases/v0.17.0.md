# Trellis v0.17.0

This minor release teaches `trellis doctor` to detect when several
`trellis` executables on PATH report different versions — the stale one
that wins PATH is the one every command actually runs.

## Changes

- **`cli-version-split` finding** — doctor scans PATH for executables
  named `trellis` (de-duplicated by realpath, order preserved), runs
  `--version` on each, and reports a finding (exit 1) when two or more
  disagree. The message lists every entry's path and version and marks
  which one a bare `trellis` invocation actually runs, with a pointer to
  reconcile the entries. Entries that can't be executed or report no
  version are skipped, never reported as a split.
- **Read-only by construction** — entrypoints are never modified, deleted,
  or upgraded; a wrapper script (e.g. a `~/.local/bin/trellis` that routes
  some subcommands elsewhere) may be deliberately maintained. The scan
  runs in `runDoctor` (CLI boundary), not `collectDoctorReport`, so
  library callers and tests never spawn processes against the real PATH.

Motivating incident: a global `agent-trellis@0.16.0` install coexisted
with a PATH-winning 0.12.0 entrypoint, which rejected the newer
`auth.client_name` key and made a version split look like a broken
`servers.yaml`.

Also in this release: the repo's `.gitignore` now covers `.mailbox/` —
agent-collab's `mailbox-server.mjs` resolves its SQLite path from
`process.cwd()`, so launching it with this repo as cwd dropped an empty
store at the repo root.

## Upgrading

CLI: `npm install -g agent-trellis@0.17.0`. If your setup has more than
one install mechanism (volta, `npm -g`, a wrapper), run `which -a trellis`
after upgrading to confirm they all agree.
