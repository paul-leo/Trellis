# Trellis v0.12.0

This release completes MCP Skills discovery/relay and desktop OAuth ownership,
and synchronizes CLI, desktop, Tauri and Cargo versions to 0.12.0.

## Changes

- SDK v2 runtime/client boundaries support modern discovery and legacy peers.
  The runtime formally advertises the Skills extension.
- Upstream skills and resources retain source identity through mapped URIs;
  files are fetched on demand and checked against manifests, sizes, digests and
  frontmatter. Resource-only peers and large valid skill files are supported.
- OAuth defaults to each Agent's own connection and credentials. Trellis hosting
  is an explicit choice and needs gateway/runtime delivery. Native authorization
  state is unknown when no official status is available; a Trellis token cannot
  authorize a native or unclassified connection.
- Desktop controls enable/clear OAuth and change ownership through confirmation.
  Hosted authorization supports browser progress, cancellation and retry, with
  Origin guards and resource/issuer-bound credentials.
- The packaged browser opener uses a static built-in import. A real binary
  verification gate covers the default opener and local PKCE grant, catching a
  pkg bytecode limitation that injected-browser source tests do not exercise.

## Upgrading

CLI: `npm install -g agent-trellis@0.12.0`.

If an older setup relied on Trellis's token store, explicitly select
`auth: { kind: oauth, owner: trellis }` and enable gateway/runtime delivery for
the receiving Agent. Otherwise, authorize the native connection in that Agent.
Dynamic upstream skill manifests are currently declined.

The macOS download is for Apple Silicon (`arm64`). It uses an ad-hoc signature
and is not notarized; macOS may require a manual security allowance on first
open. No installed application is replaced automatically.

## Validation

- 850 core tests, 52 sidecar tests, 9 GUI smoke tests and a real Chrome OAuth
  workflow passed on the merged release tree.
- Root/frontend/sidecar typechecks and builds passed; the real npm tarball
  installed and ran without dev dependencies.
- The built Sidecar and the copy inside the signed app both completed a local
  PKCE/resource/issuer grant through the production browser-opener path.
- The app's deep signature, 0.12.0 bundle metadata and DMG checksum were verified.
- The app launched from its canonical path with an isolated HOME and a live
  bundled sidecar. Production credentials were not used during validation.
