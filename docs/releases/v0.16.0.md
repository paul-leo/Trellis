# Trellis v0.16.0

This minor release teaches `trellis doctor` to validate the TOML syntax of
a workspace's `.codex/config.toml` — before Codex itself refuses to start.

## Changes

- **`workspace-toml-invalid` finding** — when a workspace layer is in
  scope and `<workspace>/.codex/config.toml` exists, doctor now parses it
  (parse-only via `smol-toml`, never round-tripped) before extracting
  entries. A parse failure is reported with the parser's line and column,
  regardless of whether Trellis rendered anything into the file, and exits
  non-zero. The message states the file was not written by Trellis and
  directs a manual fix; Trellis never repairs a file it doesn't own.
- **No more misleading unmigrated hints** — a file that can't be parsed
  is no longer also listed under "entries Trellis didn't render" (which
  would have suggested `migrate --workspace` as the fix for a syntax
  error).
- **Runs without `~/.trellis/`** — the check fires whenever a workspace
  root (a directory containing `.agents/`) is discoverable from the cwd,
  even with no global canonical source installed.

Motivating incident: a duplicate `enabled` key in a hand-edited
`.codex/config.toml` silently broke every Codex session on that project
for ~19 hours; nothing surfaced it until the next session failed.

## Upgrading

CLI: `npm install -g agent-trellis@0.16.0`. JSON project configs
(`.mcp.json`, `.pi/mcp.json`, etc.) are intentionally out of scope — they
already tolerate unparseable content by design.
