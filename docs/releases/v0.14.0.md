# Trellis v0.14.0

This release delivers MCP to pi natively: on pi ≥ 1.1.0, Trellis writes
`~/.pi/agent/mcp.json` directly and retires the pi-bridge extension in the
same sync. Older pi versions keep the bridge exactly as before.

## Changes

- `PiAdapter` probes the installed pi version. On pi ≥ 1.1.0,
  `trellis mcp sync` writes native `mcp.json` entries through the shared
  JSON-merge machinery — ownership ledger, conflict detection, and
  preservation of user-authored entries all apply. On older (or
  unprobeable) pi, delivery falls back to the bridge extension unchanged.
- The bridge symlink is removed in the same apply as the first native
  write, ordered after the config update and withheld entirely on any
  conflict — the two delivery paths never coexist (which would double
  register every tool) and pi is never left with neither.
- Native delivery exposes what the bridge dropped: MCP resources and
  prompts now reach pi (131 tools + 271 resources observed on the gateway
  route, versus tools-only through the bridge).
- Agent-owned OAuth servers (e.g. scalar `auth: oauth`) are written as
  bare `{url}` entries that pi authorizes itself via `pi mcp login <name>`
  into its own `~/.pi/agent/mcp-auth.json` — matching the v0.12 ownership
  semantics. Trellis-owned servers continue to ride the gateway/runtime
  edge.
- `trellis mcp sync` prints a hint to restart pi or run `/reload` when
  pi's mcp.json changes — pi does not watch the file.
- `PiAdapter.verify` reports mcp.json drift (missing or altered desired
  entries, stale Trellis-owned entries, a surviving bridge symlink under
  native delivery); user entries are never flagged.

## Upgrading

CLI: `npm install -g agent-trellis@0.14.0`.

pi ≥ 1.1.0 users: run `trellis mcp sync` once to migrate — it writes
mcp.json and removes the bridge atomically, then restart pi or run
`/reload`. For agent-owned OAuth servers, run `pi mcp login <name>` once.
pi < 1.1.0 users: no action; the bridge keeps working until the follow-up
release that removes it.
